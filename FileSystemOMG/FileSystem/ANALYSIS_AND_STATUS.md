# Анализ проекта и статус работоспособности

## 📋 Общая информация

**Проект:** Система управления документами компании  
**Технологии:** Flask (Python), SQLite, HTML/CSS/JavaScript  
**Статус:** ✅ Backend реализован, фронтенд полностью интегрирован

---

## ✅ Реализованные компоненты

### 1. База данных (SQLite)
**Статус:** ✅ Готова и настроена

**Таблицы:**
- `users` - пользователи с ролями (admin, manager, user)
- `departments` - отделы компании
- `document_types` - типы документов
- `internal_documents` - внутренние документы
- `external_documents` - внешние документы
- `notifications` - уведомления

**Особенности:**
- Внешние ключи включены
- Индексы для оптимизации
- Триггеры для автоматического обновления `updated_at`
- Поля `expiry_date` для сроков документов
- Пароли хранятся в виде хешей

**Расположение:** `database/documents.db`

---

### 2. Backend (Flask)
**Статус:** ✅ Полностью реализован

**Структура:**
```
backend/
├── app.py              # Главный файл приложения
├── config.py           # Конфигурация
├── models/             # Модели данных
│   ├── user.py
│   ├── document.py
│   ├── department.py
│   ├── document_type.py
│   └── notification.py
├── routes/             # API endpoints
│   ├── auth.py         # Авторизация
│   ├── documents.py    # CRUD документов
│   ├── references.py   # Справочники
│   ├── notifications.py # Уведомления
│   ├── filesystem.py   # Файловая система
│   ├── search.py       # Поиск
│   └── stats.py        # Статистика
├── services/           # Бизнес-логика
│   ├── file_manager.py # Управление файлами
│   ├── permissions.py  # Проверка прав
│   └── notifications.py # Логика уведомлений
└── utils/              # Утилиты
    ├── db.py           # Работа с БД
    ├── middleware.py   # Middleware
    └── validators.py   # Валидация
```

**API Endpoints (все реализованы):**

**Авторизация:**
- `POST /api/auth/login` - вход
- `POST /api/auth/logout` - выход
- `GET /api/auth/me` - текущий пользователь

**Документы:**
- `GET /api/documents` - список с фильтрами
- `GET /api/documents/{id}` - детали
- `POST /api/documents` - загрузка файла
- `PUT /api/documents/{id}` - обновление
- `DELETE /api/documents/{id}` - удаление
- `GET /api/documents/{id}/download` - скачивание

**Справочники:**
- `GET /api/departments` - отделы
- `GET /api/document-types` - типы документов

**Уведомления:**
- `GET /api/notifications` - список
- `GET /api/notifications/unread` - непрочитанные
- `PUT /api/notifications/{id}/read` - отметить прочитанным
- `DELETE /api/notifications/{id}` - удалить

**Файловая система:**
- `GET /api/filesystem/tree` - древовидная структура
- `GET /api/filesystem/path` - содержимое пути
- `GET /api/filesystem/browse` - просмотр

**Поиск:**
- `GET /api/search/catalog` - поиск по каталогам
- `GET /api/search/content` - поиск по содержимому

**Статистика (админ):**
- `GET /api/stats/overview` - общая статистика
- `GET /api/stats/departments` - по отделам
- `GET /api/stats/sources` - по источникам

**Особенности:**
- CORS настроен для работы с фронтендом
- Session-based авторизация
- Middleware для проверки прав (`@login_required`, `@admin_required`)
- Автоматическое создание структуры папок при загрузке
- Валидация файлов (размер, расширение)

### 3. Фронтенд (HTML/CSS/JavaScript)
**Статус:** ✅ Полностью интегрирован

**Что работает:**
- ✅ Авторизация через API (`/api/auth/login`)
- ✅ Проверка доступности сервера (`/api/health`)
- ✅ Загрузка дерева файловой системы (`/api/filesystem/tree`)
- ✅ Поиск документов (`/api/search/catalog`)
- ✅ Получение деталей документа (`/api/documents/{id}`)
- ✅ Список документов - загрузка через API (`/api/documents`)
- ✅ Личный кабинет - данные из API
- ✅ Статистика - данные из API (для админа)
- ✅ Уведомления - загрузка через API (`/api/notifications`)
- ✅ Загрузка документов - полноценная загрузка через FormData
- ✅ Удаление документов - через API

**Что НЕ реализовано:**
- ⏳ Редактирование документов - только просмотр и удаление
- ⏳ Поиск по содержимому - использует статические данные
- ⏳ Классификация - не реализована (только UI)

**Проблемы:**
1. Функция `loadDocumentsContent()` использует статический массив вместо API
2. Функция `loadPersonalContent()` использует статические данные
3. Функция `loadStatsContent()` показывает заглушки
4. Уведомления не загружаются из API
5. Модальное окно загрузки не отправляет данные на сервер

**Статус:** ✅ Настроено

**Структура:**
```

├── internal/           # Внутренние документы
│   └── {department}/
│       └── {year}/
│           └── {type}/
│               └── {date}/
```

**Особенности:**

- Поддержка форматов: doc, docx, pdf, rtf, txt, xlsx, jpg, jpeg

- `users` - 3 поля для ролей (admin, manager, user)
- `departments` - справочник отделов
- `document_types` - справочник типов документов
- `internal_documents` - внутренние документы с полями:

  - `status` - active/archived/deleted
- `external_documents` - внешние документы
- `notifications` - уведомления с типами:
  - document_received
  - document_sent
  - expiry_warning

**Связи:**
- Все внешние ключи настроены
- Каскадное удаление не используется (soft delete)

**Индексы:**
- По `document_type_id`, `department_id`, `author_id`, `document_date`, `status`
- Оптимизированы для быстрого поиска
