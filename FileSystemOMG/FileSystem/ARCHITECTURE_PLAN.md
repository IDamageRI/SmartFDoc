# План архитектуры системы управления документами

## 📋 Подтверждение требований

### Функциональные требования:

1. **Авторизация**
   Администратор создаёт учётные записи для всех пользователей, чтобы не было нелигитимных
   Далее по выданным логинам/паролям пользователи входят, роли у них уже определены администратором

2. **Просмотр документов** согласен
   - Отображение списка документов из БД
   - Фильтрация и сортировка по атрибутам
   - Скачивание файлов

3. **Загрузка документов** согласен
   - Загрузка файлов с заполнением метаданных
   - Автоматическое сохранение в файловую систему по структуре
   - Сохранение метаданных в БД

4. **Уведомления** согласен
   - О полученных/отправленных документах
   - О приближении сроков истечения документов

5. **Файловая структура** согласен
   - Древовидная организация файлов по атрибутам
   - Просмотр структуры в веб-интерфейсе
   - Синхронизация с БД

## 🔌 API Endpoints (предварительный план)  оставить возможность их сделать, пока в планах

### Авторизация
```
POST   /api/auth/login          # Вход в систему                         
POST   /api/auth/logout         # Выход
GET    /api/auth/me             # Текущий пользователь
POST   /api/auth/refresh        # Обновление токена (если JWT)
```

### Документы
```
GET    /api/documents           # Список документов (с фильтрами)                
GET    /api/documents/{id}      # Детали документа
POST   /api/documents           # Создание записи + загрузка файла
PUT    /api/documents/{id}      # Обновление метаданных
DELETE /api/documents/{id}      # Удаление (soft delete)
GET    /api/documents/{id}/download  # Скачивание файла
```

### Фильтрация и сортировка
```
GET    /api/documents?department_id=1&type_id=2&date_from=2024-01-01&sort=date_desc
```

Параметры фильтрации:
- `department_id` - отдел
- `type_id` - тип документа
- `author_id` - автор
- `date_from`, `date_to` - диапазон дат
- `status` - статус
- `category` - internal/external
- `sort` - сортировка (date_asc, date_desc, title_asc, etc.)

### Файловая структура
```
GET    /api/filesystem/tree           # Древовидная структура
GET    /api/filesystem/path?path=...   # Содержимое папки
GET    /api/filesystem/browse          # Просмотр как файловый менеджер
```

### Справочники
```
GET    /api/departments        # Список отделов
GET    /api/document-types     # Типы документов
GET    /api/users              # Пользователи (с фильтрами по правам)
```

### Уведомления
```
GET    /api/notifications              # Список уведомлений
GET    /api/notifications/unread       # Непрочитанные
PUT    /api/notifications/{id}/read    # Отметить как прочитанное
DELETE /api/notifications/{id}        # Удалить уведомление
```

## 🔔 Система уведомлений
полностью соглашаемся с текущим планом уведомлений
### Типы уведомлений:

1. **Получение документа**
   - При создании документа, где пользователь = получатель           
   - При создании документа для отдела пользователя

2. **Отправка документа**
   - Подтверждение успешной загрузки                              
   - Уведомление получателей

3. **Сроки документов**
   - Требуется добавить поле `expiry_date` в таблицы документов   
   - Уведомления за N дней до истечения (настраиваемо)               

### Реализация:

**Вариант 1: Таблица уведомлений в БД**
```sql
CREATE TABLE notifications (
    id INTEGER PRIMARY KEY,
    user_id INTEGER,
    type TEXT,  -- 'document_received', 'document_sent', 'expiry_warning'
    title TEXT,
    message TEXT,
    document_id INTEGER,
    is_read BOOLEAN DEFAULT 0,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (user_id) REFERENCES users(id),
    FOREIGN KEY (document_id) REFERENCES internal_documents(id) 
        OR document_id REFERENCES external_documents(id)
);
```

### Планировщик проверки сроков:
- Фоновый процесс (cron job / celery / APScheduler)
- Проверка документов с `expiry_date` в ближайшие N дней
- Создание уведомлений для ответственных

## 🔄 Процесс загрузки документа    

### Алгоритм:

1. **Получение файла** (multipart/form-data)
2. **Валидация файла:**
   - Размер (до 10МБ)
   - Расширение (doc, docx, pdf, rtf, xlsx, jpg) - все поступающие файлы потом конвертируются в doc, docx и pdf
3. **Получение метаданных:**           
   - Тип документа
   - Отправитель
   - Отдел
   - Автор (из сессии)
   - Получатель 
   - Дата документа

4. **Генерация пути файла:**
   ```python
   path = f"storage/{category}/{year}/{department}/{doc_type}/{filename}" опредлена выше структурой
   ```

5. **Создание директорий** (если не существуют) да

6. **Сохранение файла** в файловую систему 

7. **Сохранение метаданных** в БД:
   - Запись в `internal_documents` или `external_documents`
   - `file_path` = путь к файлу
   - `file_size` = размер файла
   - `file_extension` = расширение
   добавление метаданных в бд при отсутствии

8. **Создание уведомлений:**
   - Для получателей документа
   - Для автора (подтверждение загрузки)

9. **Возврат результата** клиенту
